# QQ 群聊增强

`astrbot_plugin_qq_enhance` 的群聊能力补充：保留关键词原文，并根据群流量选择群级清醒、用户级清醒或每次显式唤醒。

## 使用

支持 AstrBot 4.27+（5.0 以下）的 `aiocqhttp` / NapCat OneBot v11 群消息。将本目录放入 AstrBot 的 `data/plugins/astrbot_plugin_qq_group_enhance`，在插件管理中加载并配置关键词。无需额外 Python 依赖。

- **将昵称关键词从 AstrBot 自带 `wake_prefix` 中移除**，仅填入本插件；核心可保留 `/` 用于指令。核心先于插件运行，同名核心前缀仍会提前删除关键词。
- 使用默认 AI 聊天时，将 `provider_settings.wake_prefix` 留空；额外 LLM 前缀仍由核心检查。
- 插件遵循 AstrBot 的白名单、会话启停和插件启停配置。可通过 AstrBot 配置档案的插件集合限制生效群。
- 可独立使用；同时启用 `astrbot_plugin_qq_enhance` 时，已准入消息会继续经过其防抖。是否合并及等待时长由 QQ 增强插件自己的防抖配置决定。

## 唤醒规则

默认统计最近 10 个**已完成分钟**的群消息数，每个整分钟滚动一次。当前分钟单独累计；无消息的分钟按 0 结算。未触发回复的用户消息也计数，每条消息计 1 次，默认排除机器人自身消息和系统通知。

| 窗口内消息数 | 模式 | 行为 |
|---:|---|---|
| 0～15 | 低流量 | 首次显式唤醒后全群共享 180 秒窗口，任何群员均可续聊或显式刷新 |
| 16～30 | 中流量 | 每位群员须显式唤醒自己，独立维护 180 秒窗口 |
| 31+ | 高流量 | 每条消息须包含关键词或 @机器人，不建立续聊窗口 |

显式唤醒包括**正文包含关键词**和直接 `@机器人`。关键词默认区分大小写；关闭 `keyword_case_sensitive` 后忽略大小写，例如 `Airi`、`airi`、`AIRI` 均可匹配。匹配不会改变发给模型的原文或删除关键词；引用内容、昵称、卡片内部文本不参与关键词匹配。普通续聊不刷新倒计时。

例如低流量时，甲发送“小爱，聊聊电影”开启共享窗口；乙无需关键词便可续聊。乙再发送“小爱”或 @机器人，会刷新全群窗口。中流量时，乙的唤醒只刷新乙自己的窗口。

低流量转中流量时，仅保留此前显式唤醒过的用户及其剩余时间；中流量转低流量时，共享剩余用户窗口中的最晚到期时间。进入高流量会清空所有清醒窗口。重载插件或重启后状态清空，需要重新唤醒。

核心标准指令照常使用。引用机器人、`@全体` 或其他核心唤醒前缀本身不会开启本插件的窗口；普通 AI 回复按上述规则判断。其他插件主动发消息或显式调用 LLM 的行为仍由相应插件负责。

## 配置

| 配置 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 插件功能开关 |
| `keywords` | `["小爱"]` | 正文包含匹配，空列表仅通过 @ 开启窗口 |
| `keyword_case_sensitive` | `true` | 是否区分关键词大小写，关闭后忽略大小写，原文保持不变 |
| `traffic_window_minutes` | `10` | 保留的已完成分钟数 |
| `low_max_messages` | `15` | 低流量消息数上限，含该值 |
| `medium_max_messages` | `30` | 中流量上限，须大于低流量上限 |
| `awake_window_seconds` | `180` | 显式唤醒后窗口持续时间 |
| `count_bot_messages` | `false` | 是否统计平台送达的机器人自身消息；自身消息始终不由本插件触发回复 |

## 开发验证

在安装了 AstrBot、pytest、pytest-asyncio 的 Python 3.12+ 环境中，于本目录运行：

```text
python -m pytest -q
ruff check .
ruff format --check .
```

测试包含真实 AstrBot 唤醒、白名单、会话和处理阶段，以及 QQ 增强防抖接入；LLM 与网络发送使用测试替身。测试会将 AstrBot 运行数据隔离到临时目录。QQ 防抖兼容测试需要同级存在 `astrbot_plugin_qq_enhance`。
