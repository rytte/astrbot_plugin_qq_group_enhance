# QQ 群聊增强

用于增强 QQ机器人的群聊能力，目前主要实现**关键词唤醒**、**Jev／SemIf／Laya 语义唤醒**和**@优化**

## 🌟 功能亮点

* **关键词唤醒**：Astrbot 自带的前缀唤醒和@唤醒会移除唤醒词和@，在一些情况下会使机器人收到的上下文变得不自然，本插件实现了唤醒词和@的保留。
* **语义唤醒**：可选 Jev 云端、SemIf 或 Laya 本地模型，让机器人结合上下文判断一句话是不是在对自己说，而不必每次输入关键词或@唤醒。
* **模型测试**：在插件页面用 Laya、SemIf 或 Jev 测试群聊唤醒，也可自定义背景、问题和候选选项，查看概率与耗时。

三种语义后端共用 `semantic_threshold` 接话概率阈值；切换后端时可依据实际群聊效果调整。
原来的 `jev_threshold`、`semif_threshold`、`laya_threshold` 已移除。升级前若设置过自定义值，请记下所需阈值并在新版配置中填入 `semantic_threshold`；AstrBot 加载新配置结构时会移除旧字段。

## 🔀 工作流程

> 以下数值皆可在配置中进行调整。

**1. 触发唤醒条件** 满足以下任一条件即可唤醒机器人：

- 引用机器人消息
- @机器人
- 触发本插件提供的关键词
- 其他插件唤醒

**2. 清醒状态（Active State）**

- **持续时间**：唤醒后进入 **180秒** 的清醒状态。
- **状态刷新**：在机器人的回复成功发送后会刷新清醒状态窗口。
- **处理逻辑**：
  - 接收到的群消息进入 **3秒防抖窗口（最多等待 6 秒）**。
  - 窗口超时后，将当前消息连同**最近30条**历史记录发送给所选语义模型。
  - 后端逐条判断是否是对机器人说的，若是则通过内部事件正式唤醒。

**3. 非清醒状态（Idle State）**

- **消息判断逻辑**：
  - 检查该消息是否距离机器人最后一条发出的消息在 **5条以内**。
  - **是**：进入 **3秒防抖窗口**，随后送入所选后端进行唤醒判断。
  - **否**：忽略或不进行处理（视具体配置而定）。
- **作用范围**：
  * 超出清醒窗口的消息。
  * 命令产生的机器人回复。

**4. 流程图**

```python
群消息
  ├─ 正常流转 → AstrBot / 其它插件 → 聊天模型请求与回复
  │                                      │
  │                              观察实际输入覆盖的消息
  │                                      ↓
  └─ 本插件观察 → 检查清醒状态或消息距离 → 待判窗口 / 判断批次 ← 清理已覆盖消息
                                         ↓
                         3 秒防抖 / 6 秒最长聚合 + 历史缓存
                               			 ↓
                                   语义判断后端
                                         ↓ 判断通过
                                   内部请求回复事件
                                      	 ↓
                                   独立模型回复任务

退出待判的消息 → 转入历史缓存，保留最近 n 条
显式唤醒跳过语义判断；本轮模型回复成功发送后进入或刷新清醒。
```

* **QQ 组件语义化**：Astrbot 原生不支持处理QQ表情、戳一戳、卡片（音乐、定位、名片等）、红包、猜拳、骰子等组件和事件消息，可以通过 [QQ 能力增强]([QQ 能力增强 - AstrBot Cloud](https://cloud.astrbot.app/plugin/rytte/astrbot_plugin_qq_enhance)) 插件执行语义化处理，有助于语义后端理解上下文。
* Jev 的接口和流程见 [Jev 语义唤醒说明](JEV.md)；本地模型配置与限制见 [SemIf 本地接入](SEMIF.md)和 [Laya 本地接入](LAYA.md)。

## 🚀 快速上手

需要 **AstrBot `>=4.27.4,<5`**、Python 3.12+，以及 `aiocqhttp` / NapCat OneBot v11。语义唤醒使用 AstrBot **本地 Agent 执行器**。当前回归测试基于 AstrBot **4.27.4**，新版本的内部接口仍需验证。

1. 将插件目录放入 `data/plugins/astrbot_plugin_qq_group_enhance`，在 AstrBot 中加载插件。
2. 打开插件配置，在 **语义唤醒**中选择后端。Jev 需填写 API Key，见 [Jev 接入与配置](JEV.md#接入与配置)；SemIf 和 Laya 的源码随插件提供，模型加载和下载统一使用 AstrBot 主程序的 Python，需在该环境中安装模型依赖。AstrBot WebUI 侧边栏的 **模型管理与测试** 页面可切换 Laya／SemIf 并下载、选择模型，也可直接测试 Jev；SemIf 支持自定义模型目录或 Hugging Face ID，见 [SemIf 本地接入](SEMIF.md)和 [Laya 本地接入](LAYA.md)。
3. 保存配置并重载插件。先 @机器人聊一句，再发送不带 @ 的追问，观察它是否接话。

## 🧪 页面测试

进入 **模型管理与测试**，选择 Laya、SemIf 或 Jev。本地预设需先下载完整；下载后可直接测试任意已下载模型，无需先切换群聊后端或重载插件。SemIf 的自定义模型使用配置中的路径与固定版本；Jev 使用配置中的请求地址、API Key，可临时填写其他固定模型版本。

- **群聊唤醒**：填写机器人 ID、称呼、阈值、历史对话和待判断消息。消息采用 JSON 数组，每条包含 `sender_id` 与 `text`，可补充 `message_id`、`mentions`、`reply` 等元数据。机器人发言的 `sender_id` 应与机器人 ID 一致。结果显示每条候选的唤醒概率和是否达到阈值；Laya／SemIf 使用与群聊相同的正反选项顺序平均分。
- **通用判断**：填写背景文本或 JSON、判断问题及 2～16 个选项（每行一项）。填写“是／否”可做二选一判断。结果显示选中的选项、各选项概率和耗时；Jev 使用原生 `choice`，本地模型使用相应的选项评分。

测试独立于群聊消息流程，不发送 QQ 消息，不保存测试输入，也不修改插件配置。首次本地测试的耗时包含模型加载；相同配置下复用独立测试进程，切换模型或卸载插件时释放。该进程与群聊模型同时使用内存／显存。云端测试会调用 Jev 服务并按服务商规则计费。

测试输入最多 64,000 UTF-8 字节，历史和候选各最多 100 条。各模型仍有自己的 Token 上限；本地群聊测试如省略较早历史会显示省略数量，通用背景或题目超限会明确报错。页面测试只评估语义概率，实际群聊还受直接唤醒、消息距离、清醒状态和会话资格等条件影响。

## 🧠 @与群聊上下文

**@机器人时模型能看到什么？** QQ 适配器通常会从正文中移除机器人自己的第一个 @。开启“保留机器人 @昵称”后，本插件会在模型可见正文前补回 `@机器人昵称`，保留原始消息链。只有一个机器人 @时同样直接进入普通模型回复，不进入 AstrBot 的“只 @ 机器人触发等待”流程；关闭后恢复 AstrBot 原有处理。

开启 AstrBot 的“群聊消息记录注入上下文”时，插件会为核心漏记的纯 @ 消息补齐原生记录，使“先发一句话、再单独 @机器人”也能带上前面的群聊内容。记录在回复防抖前完成，已有记录不会重复添加，无需修改 AstrBot 源码。
